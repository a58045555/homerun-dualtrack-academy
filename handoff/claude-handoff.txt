# 小小探索學院・Claude 交接包

這個資料包包含可執行網站、音檔、測試、教材來源、需求、發布證據與待辦，沒有帳密或孩子的瀏覽器紀錄。

## 用 Claude 網頁／手機聊天
1. 先上傳「Claude交接說明.txt」，再貼「給Claude的交接指令.txt」。
2. 完整ZIP供下載、備份及Claude Code解壓使用；一般聊天不應假設能直接讀取ZIP。
3. Claude如需看程式，可從GitHub取得相關檔案，或由你解壓後上傳「文字原始碼」中的對應TXT。先給相關檔案，避免一次塞入整個大型題庫。

## 用 Claude Code
1. 解壓縮後，在 project 目錄開啟 Claude Code。
2. 它可從 CLAUDE.md 讀取專案說明。把同一段交接指令貼給它。
3. 先跑 node handoff/VERIFY_PACKAGE.cjs 與 node run-checks.cjs --quick。預覽用 node preview.cjs。

# 平板啟動相容性修正（2026-10-22）

已確認的程式問題：app.js含兩個正規表示式lookbehind常值。Safari在16.4才加入支援；舊版即使沒有執行到該功能，也可能在解析整份腳本時失敗，使首頁無法啟動。來源：https://webkit.org/blog/13966/webkit-features-in-safari-16-4/

# Codex × Claude 合作方式

1. 先由使用者決定本輪負責者與任務。另一方可閱讀、審查、驗證，不同時改同一份app.js。
2. 每次先讀STATUS.json並確認最新遠端提交；檔案可能已被另一方更新。保留既有改動，不做git reset --hard或整目錄覆蓋。
3. 建議一個任務一個分支，透過diff／commit交接，不直接傳一份來歷不明的新app.js覆蓋原版。
4. 交回格式：問題與重現條件、修改檔案、行為前後差異、測試命令與結果、實機型號／瀏覽器、仍未確認之處、commit或patch。
5. 題庫修改先核對語意與正解，再更新稽核記錄；不能以測試通過或重算雜湊代替內容審核。
6. 確認發布負責者。不要兩方同時部署、改網域或換Vercel團隊；不把孩子紀錄、憑證或家長錄音放進GitHub。
7. 如果只有Claude網頁聊天，請回傳明確patch或修改後檔案清單，並附驗證步驟，交由能執行測試的一方確認。

目前建議第一項任務：Claude釐清實體平板問題，Codex或另一方審查差異並協助回歸驗證。這只是建議分工，沒有自動替使用者啟動另一個AI或傳送訊息。
